# 臺股強勢掃描（雲端版）

這個資料夾是使用者自己的「臺股強勢掃描」程式。它和運動分析是不同的專案，只是借用這個存放庫的
GitHub Actions 與 GitHub Pages 在雲端執行，所以不用開電腦，手機也能看。

- 網頁：https://panchiyu1-cloud.github.io/sports-analyzer/stock/
  - 網頁檔案放在 `docs/stock/`。
- 資料：由 `.github/workflows/stock.yml` 產生。
  - 平日盤中每分鐘更新一次，推到 `stock-data` 分支。
  - 網頁直接讀這個分支上的 JSON 檔。
- 程式：
  - `twscan/` 和電腦版完全相同。
  - `cloud.py` 是雲端執行與輸出資料的部分。
  - `config.json` 是設定（手續費折扣等）。
- 手機推播：設定存放庫的 `STOCK_NTFY_TOPIC` secret 後才會推播。
  - 這個 secret 和運動分析的 `NTFY_TOPIC` 分開。
  - 主題名稱等同密碼，不會寫進任何檔案或紀錄。
- 我的持倉與交易紀錄：只存在手機瀏覽器裡（localStorage），雲端主機看不到。
- 10 秒報價（選用）：
  - GitHub 一分鐘只能更新一次，所以另外用使用者自己的 Google Apps Script 轉播站（`relay/Code.gs`）。
  - 雲端每 10 秒送報價過去，網頁每 10 秒去讀。
  - 轉播站網址要設成 GitHub 的 `STOCK_RELAY_URL` secret，也要在網頁「模型與資料 → 10 秒報價」貼一次。
  - 網址等同密碼。

## 開盤前試撮（08:30–09:00）

證交所 08:30 開始接受委託，每 5 秒揭示一次模擬撮合的結果（試算成交價、張數、最佳五檔），09:00 才真的開盤。

- `twscan/preopen.py` 把每檔這 30 分鐘的試撮價量記下來，換算成預估的開盤漲跌，並判讀：
  小幅開高可留意、開太高勿追、開低先觀望、量太少不準、價格忽高忽低。
- 網頁「強勢前十」最上面在平日 08:25–09:40 顯示：昨天收盤後選出的前 10 名今天預估怎麼開，
  以及模型分數較高、試撮轉強的股票。開盤後多一欄「實際開盤」，並算出試撮和實際開盤差多少。
- 每天 09:10 之後存一份對照（`data/live/preopen/日期.json`），之後可以回頭檢查判讀規則準不準。
- 判讀規則還沒有用歷史資料驗證。試撮不是成交，開盤前可以撤單。
- `preopen.json` 裡的 `samples` 是幾檔股票的證交所原始欄位，用來核對 `pz`（試撮價）、`ps`（試撮張數）
  這些欄位在試撮時段的意思。

### 怎麼確保 08:30 以前就在執行

GitHub 的排程常常晚幾個小時才啟動，不能靠它。使用者的手機每天 08:00 會上傳運彩資料（`data/tw/`），
上傳會立刻啟動工作，所以 `stock.yml` 也跟著這個上傳啟動：平日早上才放行，等到 08:18 開始，
一路跑到 14:10。排程仍然保留，當作哪天沒有上傳時的備援。

## 模擬戰（當沖）

網頁的「模擬戰」分頁：一個假想的帳戶（35 萬元），照「當沖模式」的「可進場」建議自動模擬買賣，
用來看那套建議的實際成績。不會真的下單。做法比照差價交易網頁的模擬戰（觀察中 → 準備中 → 交易中 → 歷史），
但這裡是雲端主機在盤中自己執行，網頁關著也照常模擬。

- 程式：`twscan/sim.py`（規則的數字都在最上面的 `DEF`）。盤中每幾秒檢查一次。
- 規則：只用帳戶裡的錢（不放大）；單筆不超過餘額的 50%；碰到停損最多賠餘額的 1%；同時最多 3 檔；
  同一檔一天一次；當天賠到 3% 停手；出現「可進場」後等 60 秒再確認才買；13:15 全部賣出。
  買賣價位用當沖模式算的那一組；手續費、證交稅都扣。
- 成交算得保守：買在賣一價；停損發現時已跌破就用買一價；停利以目標價成交；兩次報價之間同時碰到算停損。
- 存檔：`data/live/sim/state.json`（帳戶、持倉、每日紀錄）與 `hist.json`（每一筆交易），
  另外備份在 `stock-data` 分支的 `state/sim/`。快取比分支舊時（上一輪被中途取消），啟動時用分支上的那一份。
- 輸出：`sim.json`（每分鐘）、`sim_hist.json`（有新交易才變）。
- 重新開始：把 `config.json` 的 `sim_reset` 改成任何新的字（例如日期），下一輪就會開一個新帳戶，
  舊紀錄另存成 `old-*.json`。起始金額是 `sim_start`（只在開新帳戶時生效）。
- 還沒驗證：規則的數字都是第一版；它的目的是累積一份誠實的成績單，不是保證會賺。

## 模擬戰的回測

`stock/backtest_sim.py` 把過去的交易日重播一遍：用的是盤中那三段程式本身（即時排名 → 當沖模式的
「可進場」→ 模擬戰的買賣），餵它 Yahoo 的 5 分 K（最多回溯約 40 個交易日）。做不到和盤中一樣的地方
寫在檔案開頭（每 5 分鐘一步、沒有外盤比、沒有當時的新聞與法人、買進算賣一價…）。

- 工作區連不到 Yahoo，所以在 GitHub 上跑：Actions →「臺股模擬戰回測」→ Run workflow（約 10 分鐘；
  同一天再跑只要 1 分鐘，5 分 K 與排名都留在它自己的快取裡）。它只讀掃描程式的快取，不會動到真正的模擬帳戶。
- 結果推到 `stock-backtest` 分支的 `sim_backtest.json`。要放上網頁：把那個檔複製成
  `docs/stock/sim_backtest.json`（網頁「模擬戰」最上面會出現「實際紀錄／回測」的切換）。
- 本機只測流程：`python3 stock/backtest_sim.py --demo --days 6 --out /tmp/bt`（假資料，數字沒有意義）。
- 第一次結果（2026-11-22，10/07–11/20 共 30 個交易日，同期加權指數 −27.7%）：79 筆、勝率 27%、
  −52,598 元（−15.0%）；樂觀算法 −10.6%；單筆上限放寬 −15.9%。
- 改法研究（同一天，`--study`；Actions 的 mode 選 study、days 填 55）：把回測拉長到 55 個交易日
  （8/31–11/20），分前後兩半（前半加權 +6.4%、後半 −26.9%）。事先講定只測四種改法，前後兩半扣成本後
  都是正的才算過關，結果都沒過關：

  | 改法 | 全期 | 前半 | 後半 |
  |---|---|---|---|
  | 現在的規則 | 162 筆 −88,999 | 95 筆 −47,342 | 67 筆 −41,657 |
  | 大盤走空不做多（月線之下、或當時不是上漲就不進場） | 64 筆 −41,751 | 56 筆 −42,884 | 8 筆 +1,133 |
  | 不追強，限價單掛當日均價等拉回 | 121 筆 −69,841 | 68 筆 −27,325 | 53 筆 −42,516 |
  | 避開一檔跳動超過股價 0.25% 的價位 | 153 筆 −68,840 | 90 筆 −30,062 | 63 筆 −38,778 |
  | 三項一起 | 39 筆 −24,658 | 34 筆 −18,232 | 5 筆 −6,426 |

  現在的規則在大盤上漲的前半段也賠，所以問題不只是大跌。改法寫在 `backtest_sim.py`（`STUDY`、`PullbackSim`），
  沒有動到盤中的程式。網頁顯示的是 `docs/stock/sim_study.json`（只留總結）。

## 更新程式

電腦版改好以後，依下列方式複製過來：
- `twscan/`、`cloud.py` 複製到 `stock/`。
- `web/` 的 `app.js`、`daytrade.js`、`sim.js`、`kchart.js`、`style.css`、`cloud.js` 複製到 `docs/stock/`。
  - `docs/stock/index.html` 是雲端版專用的（電腦版資料夾裡的 `web/index.cloud.html`），不要用電腦版的 `index.html` 覆蓋。
  - 改了 js 或 css，把 `index.html` 裡每個檔名後面的 `?v=` 換成新的數字（GitHub Pages 會快取約 10 分鐘）。

## 本機測試

```bash
python stock/cloud.py --demo-live --minutes 2 --publish-dir /tmp/pub --no-push
```

這會用模擬資料寫出 JSON。網頁加上 `?data=` 參數，就可以讀本機的資料夾。

模擬戰的測試（不連網路）：

```bash
python3 stock/tests/test_sim.py       # 核心規則：部位大小、成交、出場、停手、存檔還原、40 天隨機對帳
python3 stock/tests/shots_sim.py      # 手機版面（需要 Playwright；準備方式寫在檔案開頭）
```

本工具僅供研究參考，不構成投資建議。
